저번 주차땐 BAS에 관한 환경 구축을 진행 했었는데 이번 주차에서는 VMware 가상 환경에 우분투(Ubuntu)를 설치하고 그 위에 통합 보안 솔루션인 Wazuh(와주)를 구축하여 실시간으로 로그를 수집하는 과정을 다뤄볼것이다. 또한  Agent를 연결하여 실제 시스템 로그가 어떤 방식으로 수집 되고 분석되는지 그 흐름을 확인 해보는 시간을 가져볼것이다.

 

 

실습 명령어를 입력하기 전에 우리가 이번 시간에 사용할 프로그램과 용어들이 무엇을 뜻하는지를 먼저 정리 해보겠다.

 

우분투(Ubuntu)란 무엇인가요?

우리가 스마트폰에서 안드로이드나 iOS를 쓰고 PC에서 윈도우(Windows)를 쓰는 것처럼 컴퓨터를 움직이게 하는 기본 핵심 프로그램을 운영체제(OS)라고 한다. 우분투(Ubuntu)는 전 세계에서 가장 많이 쓰이는 무료 오픈소스 운영체제인 '리눅스(Linux)'의 한 종류입니다. 일반적인 윈도우와 달리 터미널을 통해 텍스트 기반으로 조작하는 경우가 많아 서버 운영에 자주 쓰인다.

Wazuh(와주)란 무엇인가요?

회사나 기관에는 수많은 컴퓨터와 서버가 존재한다. 이 컴퓨터들이 해킹을 당하고 있는지 이상한 명령어가 실행되고 있는지 한곳에 모아서 감시하고 분석해 주는 오픈소스 보안 플랫폼이다.

 

All-in-One(올인원) 방식인 이유는 무엇인가요?

원래 큰 기업에서 Wazuh를 쓸 때는 분석하는 컴퓨터, 저장하는 컴퓨터, 화면을 보여주는 컴퓨터를 각각 따로 구비한다. 하지만 우리는 공부하는 단계이므로 이 모든 기능을 우분투 가상 컴퓨터 딱 한 대에 전부 모아서(All-in-One) 설치하는 것이다.

Wazuh 서버를 올릴 우분투 운영체제를 가상머신에 먼저 설치해야 한다. 

가상머신인 VMware의 설치 과정은 지난주차 블로그에 올려뒀으니 참고 하길 바란다.

빨간색 네모를 클릭하여 설치를 해준다.

Installer disc image file을 선택하고 브라우저에서 아까 다운 받았던 우분투.iso를 찾아서 선택 해주고 [Nezt]를 눌러준다.

 

 

사용자 정보를 입력하는 창이 나옵니다.

  • Full name: 본인 이름 (영문)
  • User name: 로그인할 아이디 (소문자 영어로 짓습니다. 예: user)
  • Password: 로그인할 비밀번호 (기억하기 쉬운 것으로 두 번 입력)

 

가상머신 이름과 저장 위치를 지정하는 창이 나옵니다. 이름은 "Wazuh-Server" 정도로 짓고 [Next]를 누른다

 

 

 기본 20GB로 되어 있을 텐데, Wazuh가 용량을 꽤 차지하므로 40GB로 넉넉하게 적어주고 [Next]를 누른다

 

 

마지막 요약 화면에서 Customize Hardware 버튼을 누릅니다.

  • Memory (RAM): 가상머신이 버벅거리지 않도록 최소 4096MB(4GB) 이상으로 바를 올려준다
  • Processor 설정: Processor 2, Core 2로 권장 드린다.
  • Network Adapter: 기본값인 NAT로 둡니다. (원래 윈도우 PC의 인터넷을 빌려 쓰는 방식이다)
  • [Close]를 누르고 [Finish]를 눌러 마무리한다.

 

이 이후부턴 필자는 이미 깔아놨기에 글로만 설명할것이다.

막힌 부분이 있다면 댓글로 달아주면 어떻게 해야하는지 알려주겠다.

 

 

[Finish]를 누르면 가상머신이 켜지면서 우분투 설치 화면이 나타난다.

까만 화면에 흰 글씨가 나오다가 우분투 로고가 뜰 것인데 VMware가 자동으로 설치를 진행해 주므로 마우스를 클릭할 필요 없이 화면이 켜질 때까지 쭉 기다린다. (사양에 따라 다른데 오래 걸릴 수 있다.)

언어 선택은 한국어가 없기에 자신이 잘 이해 할 수 있는 언어로 해준다. 필자는 English로 쓸 예정이다

 

그리고 Done을 거의다 골라주고 Skip 할 수 있는건 다 해준다.

그리고 Storage에서 Use an entire disk를 고르고 Done을 선택 해준다. 

하다 보면 Profile Setup이 나올텐데 잘 입력해주고 Done을 입력 해준다.

SSH 설정하는 부분도 Install OpeneSSH server을 선택하고 Done을 선택해준다.

이제 우분투가 설치 될텐데 10~20분정도 걸릴테니 기다려준다. 그리고 설치가 완료 되면 Reboot Now를 선택해준다.

이제 오늘의 핵심인 Wazuh를 설치 할것이다.

//curl 설치
sudo apt install curl -y
//설치 스크립트 다운로드
curl -sO https://packages.wazuh.com/4.14/wazuh-install.sh

chmod +x wazuh-install.sh

 

이렇게 설치를 다 마췄다면 Wazuh All-in-One을 설치를 해준다.

 

sudo bash wazuh-install.sh -a

이렇게 하면 설치를 시작한다. 설치가 오래 걸리니 멈춘 것 처럼 보여도 기다려준다.

 

 

이제 모두 설치가 끝났다면 아이디와 비밀번호가 나올텐데 메모를 해준다.

이제 서비스들의 상태를 확인 해줄것이다.

 

sudo systemctl status wazuh-manager
sudo systemctl status wazuh-indexer
sudo systemctl status filebeat
sudo systemctl status wazuh-dashboard

하나씩 입력 해주면 하나만 확인 해주면 되는데 

이렇게 Active : active (running) 상태만 다 확인 해주면 된다.

 

 

차례대로 역할은

wazuh-manager : Agent 이벤트 수집 및 룰 기반 분석을 담당한다.

wazuh-indexer : Alert 및 이벤트 데이터를 저장한다.

filebeat : Wazuh Manager의 Alert 데이터를 Indexer로 전달한다.

wazuh-dashboard : 웹 기반 Dashboard 접속을 제공한다.

 

 

포트 확인

sudo ss -tulnp

포트 확인은 데이터가 통신할 길이 제대로 뚫려 있는가? 를 확인하는 작업입니다.

모든 프로그램이 설치 되어 있어도 특정 포트들이 닫혀 있으면 데이터가 넘어가지 않기에 잘 확인 해줘야 한다.

각 포트는 정해진 역할이 있습니다.

  • 443/TCP: Dashboard 접속 (내가 데이터를 보는 문)
  • 1514/TCP: Agent에서 Manager로 로그 전달 (데이터 유입 통로)
  • 1515/TCP: Agent 인증 (등록하는 열쇠)
  • 55000/TCP: API 통신 (시스템 간 대화 창구)
  • 9200/TCP: Indexer 통신 (저장소로 가는 입구)

이렇게 홈 화면으로 다시 돌아오면 windows가 Active 상태인걸 확인 할 수 있다.

이제 현재 자기 자신 PC의 터미널(관리자권한)이나 PowerShell(관지라권한)에 그대로 복사한걸 붙여주고 실행 시켜주면 된다.

필자는 이미 서비스를 시작을 해놨기에 이렇게 뜨는것을 확인 할 수 있다.

 

이제 대상 컴퓨터에서 일어나는 일들이 서버로 잘 넘어오는지 테스트를 해볼거다.

아래의 명령어들을 차례대로 입력 해보자

whoami
hostname
ipconfig
net user

 

이렇게 명령어들을 실행 시키면 Wazuh dashboard에 로그가 찍히게 된다.

Wazuh에 왼쪽 상단에 3개의 바를 눌러 Discover를 누른다. 

그럼 이렇게 시간대별, 혹은 검색을 통해서 로그들을 확인 할 수 있다. 여기서 검색한 명령어들의 로그들을 볼 수 있다. 하지만 필자는 Wazuh가 정상적인 시스템 조회 명령어(whoami 등)는 위험도가 낮아 대시보드에 기록되지 않기에 실제 해커들이 시스템 장악 후 수행하는 '무단 계정 생성' 시나리오를 가상으로 유발하여 로그 수집을 검증해보겠다.

 

  • 테스트 환경: Windows 11 Host (Pxjeong_Windows, IP: 192.168.10.1)
  • 실행 명령어 (관리자 권한 CMD)
net user hacker_test [비밀번호 가림] /add

 

이렇게 CMD에다 테스트겸 계정을 생성하고 로그를 확인해보자.

이렇게 생성된걸 확인 할 수 있고

net user hacker_test /delete

다시 계정을 지워보고 로그를 확인해보면 

계정이 지워진 로그를 확인 할 수 있다.
