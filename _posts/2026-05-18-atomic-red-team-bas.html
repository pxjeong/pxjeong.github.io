이번 실습에서는 단순히 Linux 명령어를 실행하는 것이 아닌 실제 공격자가 시스템 내부에서 수행하는 정보 수집 Atomic Red Team을 이용하여 재현해볼 예정이다.

이론

Atomic Red Team이란?

먼저 Atomic Red Team에 대해 간단하게 설명 해보자 Atomic Red Team은 MITRE ATT&CK 기반의 공격 시뮬레이션 도구이다.

여기서 MITRE ATT&CK란 실제 공격자들이 사용하는 공격 기법들을 정리해놓은 프레임워크라고 볼 수 있다.

 

예를 들어 공격자는 시스템 침투 이후 가장 먼저

  1. 현재 로그인된 사용자 확인
  2. 운영체제 종류 확인
  3. 네트워크 구조 파악
  4. 중요 파일 위치 탐색

같은 행동들을 수행하게 된다. Atomic Red Team은 이러한 공격자의 행동들을 작은 단위로 직접 테스트할 수 있도록 만들어진 도구이다.

  • MITRE ATT&CK = 공격 기법 이론
  • Atomic Red Team = 실제 공격 기법 실습

이번 실습에서는 총 4개의 ATT&CK Technique를 분석하였다.

 

기술 설명
T1082 시스템 정보 수집 ( 공격자가 대상 환경을 파악하는 단계 분석 가능 )
T1033 현재 사용자 정보 확인 ( 계정 정보 수집 행위 분석 가능 )
T1083 파일 및 디렉터리 탐색 ( 공격자가 민감 파일이나 경로를 찾는 행위 분석 가능 )
T1016 네트워크 설정 정보 수집 ( 공격자가 내부 네트워크 구조를 파악하는 단계 분석 가능 )
T1049 네트워크 연결 상태 확인 ( 공격자가 현재 연결된 세션이나 통신 상태를 파악하는 행위 분석 가능 )

 

이러한 정보들은 공격자가 추가 공격을 수행하기 전 반드시 수집하는 정보들이기 때문에 전 주차때 설명한 정찰 단계에서 매우 중요하게 사용된다.

 

이번 실습에서는 이러한 ATT&CK Technique들을 직접 테스트하기 위해 VMware 기반의 가상 환경을 구축하였다.

실제 공격 시뮬레이션은 운영 중인 PC 환경에서 바로 수행하기에는 위험 하기에 일반적으로는 VMware와 같은 가상화 환경을 사용하여 가상환경을 구성하게 된다.

실습

먼저 VMware를 설치해야 한다.

  • VMware Workstation

VMware는 PC 안에서 여러 운영체제를 동시에 실행할 수 있게 해주는 가상화 하는 프로그램이다

쉽게 말하면 "컴퓨터 안에 또 다른 가상 컴퓨터를 만드는 프로그램" 이라고 설명 할 수 있다.

 

다음으로 VMware 안에서 사용할 Linux 운영체제를 설치해야 한다.

이번 실습에서는 Rocky Linux를 사용하였다. Rocy Linux는 기업 서버 환경에서도 자주 사용되고 많은 Linux 배포판중 하나이며, 보안 실습이나 서버 환경 구축 실습에서도 많이 활용 된다.

Rocky Linux ISO 파일은 공식 사이트에서 다운로드 가능하다.

  • Rocky Linux Download

 

이렇게 모두 깔았다면 VMware를 들어가서 File을 눌러서 New Virtual Machine을 누르거나

Home 탭에 Create a New Virtual Machine을 눌러준다.

그리고 Rocky를 깔아주기 위한 설정들을 해준다.

 

 

이렇게 Rocky Linux를 설치를 다 마쳤다면 VMware를 부팅해준다.

 

부팅을 다 했다면 깔았던 Rocky Linux 9.5(최신 버전)을 선택 해준다.

느낌표 표시들을 하나씩 눌러주어 모두 설정을 해준다. 그러고 나서 설치 시작(B) 버튼을 눌러서 설치를 끝내주면 설치가 다 끝나게 된다.

이제 Atomic Red Team 실습 환경 구성을 진행을 해보자 Linux 서버는 Windows처럼 프로그램을 클릭해서 설치하는 방식보다는 명령어를 이용하여 필요한 도구들을 직접 설치하면서 환경을 구성하게 된다.

이번 실습에서는 먼저 Git이라는 프로그램을 설치하였다.

 

Rocky Linux 화면에서 윈도우 키를 눌러서 터미널 모양을 눌러서 터미널을 열어준다.

 

그리고 터미널에 다음과 같은 명령어들을 입력해준다.

sudo dnf install git -y

sudo => 관리자 권한으로 실행한다.

dnf => Rocky Linux 패키지 설치 명령어

install => 프로그램 설치 수행

git => GitHub 프로젝트 다운로드 도구

-y => 설치 과정에서 자동으로 Yes 처리

“관리자 권한으로 Git 프로그램을 설치하겠다” 라는 의미의 명령어들이다.

 

여기서 의문점이 드는 사람들이 있을텐데 그렇다면 왜 Git을 설치해야 할까?

Atomic Red Team은 GitHub라는 오픈소스 저장소 사이트에서 제공된다.

GitHub는 개발자들이 프로그램이나 프로젝트 파일을 공유하는 플랫폼이고 Atomic Red Team 또한 GitHub에 공개되어 있다.

Git을 이용하면 GitHub에 올라와 있는 Atomic Red Team 프로젝트 전체를 Linux 환경으로 다운로드할 수 있게 된다.

또한 Git은 실무에서도 많이 사용한다.

  • Atomic Red Team GitHub  Atomic Red Team 공식 GitHub 주소

 

 

Git 설치가 완료 되면 이제 Atomic Red Team 프로젝트를 다운로드를 한다.

git clone https://github.com/redcanaryco/atomic-red-team.git

 

git clone => GitHub 저장소 전체 다운로드(복사) 를 의미한다.

이렇게 다운로드 하게 된다면

atomic-red-team

이라는 폴더가 생성되는 것을 볼 수 있다.

이후 현재 폴더 안 파일 목록을 확인 하는 명령어인 ls를 입력하면 확인 할 수 있고 여기서 atomic-red-team 폴더가 보이면 정상적으로 다운로드가 완료된 것이다.

 

다음 단계로 Atomic Red Team 폴더 내부로 이동하여 실제 ATT&CK Techique 테스트 파일들을 분석 해볼거다.

cd atomic-red-team

여기서 cd는 Change Directory의 약자로 현재 작업 위치를 변경 한다는 의미이다. 지금 하는 작업은 Atomic Red Team 실습 파

일이 존재하는 작업 공간으로 이동하는 과정이다.

cd atomics

를 입력 하면 ATT&CK Technique별 테스트 파일들이 저장된 폴더로 이동할 수 있다. 이제 여기서 현재 위치나 특정 경로의 디렉토리의 내용의 리스트를 출력하는 명령어인 ls를 입력 하면

ls

=> 결과

T1016
T1033
T1049
T1082
T1083
//등등

등등 많은 Technique 폴더들이 존재하는 것을 확인할 수 있다.

첫 번째로 T1082(System Information Discovery)를 분석하였다. T1082는 시스템 정보 분석 방법으로 정보를 수집하는 공격 기법이다. 공격자는 시스템 정보를 확인함으로써 Linux인지 Windows인지, 어떤 버전인지, 얼마나 오랫동안 켜져 있었는지 등등을 분석해서 이후 사용할 공격 방식을 결정 할 수 있다.

uname -a

이 명령어는 현재 시스템의 커널 및 운영체제 정보를 출력하는 명령어이다.

 

이렇게 나오면 정상이다.

cat /etc/os-release

이 명령어는 Linux 배포판 정보를 확인하는 명령어이다. 현재의 Rocky Linux 환경 정보를 확인 할 수 있다.

 

uptime

이 명령어는 시스템이 얼마나 오랫동안 실행 되고 있었는지를 확인 하는 명령어이다.

공격자는 서버 uptime 정보를 통해서 재부팅 여부, 운영 상태, 서버 안정성 등을 추측 할 수 있다.

 

 

이러한 명령 실행 이후에는 단순 출력 결과만 보는 것이 아닌 시스템에 어떤 흔적들이 남았는지도 함께 분석해야한다.

Linux에서는 사용자가 입력한 명령들이 history에 저장된다.

history

이러한 명령어를 입력 하거나

cat ~/.bash_history

이 명령어를 입력 하면 실행 흔적들을 확인 할 수 있다.

 

 

이제 두번째 ATT&CK Technique인 T1033(System Owner/User Discovery)를 분석해보겠다.

이 기법은 현재 사용자 정보 확인을 하는 단계이다. 실제 공격자는 시스템 침투 이후 가장 먼저 현재 로그인 사용자, 관리자(root) 권한 여부, 활성 사용자 목록 등을 확인하게 된다.

이러한 정보들은 이후 권한 상승(Privilege Escalation) 공격이나 계정 탈취 공격 과정에서 매우 중요하게 사용된다.

 

whoami

이 명령어는 현재 로그인되어 있는 사용자 계정을 출력한다.

현재 내가 어떤 계정으로 시스템을 사용 중인지를 확인하는 명령어이다.

id

이 명령어는 사용자 ID, 그룹 ID, 현재 속한 권한 그룹등을 출력하는 명령어이다.

특히 사용자가 wheel 그룹이나 root 권한과 관련된 그룹에 포함되어 있는 경우 공격자는 관리자 권한 획득 가능성을 분석할 수 있다. (wheel 그룹이란 일반 사용자가 최고 관리자 권한(sudo, su 등)을 일시적으로 대행할 수 있도록 허가 받은 관리자 그룹)

 

who

이 명령어는 현재 시스템에 로그인 되어 있는 사용자 목록을 출력하는 명령어이다.

공격자는 이를 통해서 현재 접속 중인 사용자, 로그인 시간, 접속 위치 등을 확인 할 수 있다.

w

이 명령어는 현재 로그인된 사용자와 함께 어떤 작업을 수행 중인지, 시스템 사용 시간, CPU 사용 정보 등을 출력한다.

공격자는 현재 사용자의 활동 상태까지 확인 할 수 있게 된다.

다음으로 분석한 ATT&CK Technique는 T1083(File and Directory Discovery)이다. 파일 및 디렉터리 탐색하는 단계이다.

실제 공격자는 시스템 침투 이후 중요 설정 파일 이라던지 계정 정보, 백업 파일 데이터 저장 위치 등을 찾기 위해서 파일 탐색을 수행한다. 특히 Linux 환경에서는 중요한 시스템 파일들이 특정 경로에 저장되어 있기에 파일 탐색은 공격 과정에서 매우 중요한 단계라고 볼 수 있다.

 

아까 전 사용했던 명령어인 ls 명령어도 여기서 사용된다.

 

find /tmp

이 명령어는 /tmp 경로 내부 파일들을 탐색하는 명령어이다. Linux의 /tmp 디렉터리는 임시 파일들이 저장되어 있는 공간이며 실제 공격자들도 악성 파일이나 임시 스크립트를 저장하는 위치로 자주 사용한다.

 

file /etc/passwd

이 명령어는 특정 파일의 종류를 분석하는 명령어이다. /etc/passwd 파일은 Linux 사용자 정보와 관련된 중요한 시스템 파일 중 하나이고 공격자는 이러한 파일들을 확인하여 계정 구조와 사용자 목록, 시스템 구성 등을 확인 할 수 있다.

 

다음으로 분석한 ATT&CK Technique는 T1016(System Network Configuration Discovery)이다. 이 기법은 네트워크 설정 정보 수집을 하는 단계이다. 실제 공격자는 시스템 침투 이후에 내부 IP 주소, 게이트웨이, DNS 정보, 내부 네트워크 구조등을 파악하여 다양한 공격을 수행 할 수 있다. 네트워크 정보 수집은 내부 확산 공격을 위한 핵심 단계라고 볼 수 있다.

 

ip addr

이 명령어는 현재 시스템의 네트워크 인터페이스와 IP 주소 정보를 출력 하는 명령어이다.

공격자는 이를 통해내부 IP 주소, 사용 중인 네트워크 인터페이스, 네트워크 대역 등을 확인할 수 있다.

 

 

route

이 명령어는 시스템의 라우팅 정보를 출력하는 명령어이다.

기본 게이트웨이, 패킷 이동 경로 등을 확인 할 수 있다. 공격자는 이 정보들을 통해 내부 네트워크 구조를 분석 할 수 있다.

cat /etc/hosts

/etc/hosts 파일은 로컬 시스템의 호스트 이름과 IP 주소 정보를 저장하는 파일이다

이 명령어는 내부 서버 이름, 내부 시스템 주소등을 파악하는 명령어이다.

.

마지막으로 분석한 ATT&CK Technique는 T1049(System Network Connections Discovery)이다. 현재 연결된 세션이나 통신 상태를 파악하는 행위 분석하는 단계이다. 실제 공격자는 시스템 침투 이후에 현재 어떤 서버와 통신 중이고 어떤 포트가 열려 있는지, 활성 네트워크 연결이 존재하는지 등을 확인하여 추가 공격 가능성을 분석하게 된다.

특히 내부 네트워크 환경에서는 현재 연결 상태를 분석함으로써 내부 서버 식별, 원격 접속 확인, 백그라운드 서비스 탐색 등이 가능하기에 매우 자주 사용되는 정보 수집 기법 중 하나이다.

 

netstat -antp

이 명령어는 현재 시스템의 네트워크 연결 상태를 출력하는 명령어이다.

 

여기서 -a => 전체 연결 표시, -n => IP 및 포트를 숫자로 출력, -t => TCP 연결 표시, -p => 프로세스 정보 출력을 의미한다.

공격자는 이를 통해서 현재 연결 중인 세션이나 서비스 상태를 분석 할 수 있다.

 

ss -ant

ss 명령어는 netstat와 유사하게 네트워크 소켓 상태를 출력하는 명령어이다. 최근 Linux 환경에서는 netstat보다 ss 명령어가 더 빠르고 자주 사용된다. 

 

공격자는 이 명령어를 통해서 활성 TCP 연결, LISTEN 상태 포트, 네트워크 통신 상태 등을 확인 할 수 있다.

 

lsof -i

이 명령어는 현재 열려 있는 파일을 확인 하는 명령어이다. Linux에서는 네트워크 연결 또한 파일처럼 관리되기 때문에 -i 옵션을 사용하면 현재 사용 중인 네트워크 연결 정보를 출력할 수 있다. 공격자는 어떤 프로그램이 네트워크를 사용 중인지와 어떤 포트와 연결 되어 있는지 등을 확인 할 수 있다.

 

추가로 이제 실행 이후에는 시스템 내부에 어떤 흔적들이 남았는지도 분석 해보자

먼저 /tmp 디렉터리를 확인 해보자 

ls -al /tmp

또는

ls /tmp

Linux의 /tmp 경로는 임시 파일 저장 공간으로 사용되며, 실제 공격자들도 악성 스크립트나 임시 파일 저장 위치로 자주 활용한다.

따라서 보안 분석 과정에서는 /tmp 경로를 우선적으로 확인하는 경우가 많다.

 

만약 자기가 txt 파일로 만들어서 결과들을 보고 싶다면

uname -a > result.txt

 

또는

whoami > user_result.txt

을 해서 ls로 확인을 하면 result.txt 파일이 생긴것을 볼 수 있다.

cat result.txt

명령어를 통해서 파일 내용을 출력을 하여 확인 할 수 있다.

 

다음으로 실행 로그(csv)를 만들어보자

간단하게 실습 로그를 남기자면

history > command_log.csv

이러면 현재까지 실행한 명령 기록들을 csv 파일 형태로 저장한것이다.

이러고 아까 전 방법과 같이 ls 와 cat command_log.csv를 써서 확인 가능하다

 

시스템 흔적 분석을 해보자

history

또는

cat ~/.bash_history

을 쓴다면 현재까지의 명령어 흔적들을 확인 할 수 있다. 이 명령어를 통해서 공격자가 공격 수행 후 시스템 내부에 흔적이 남는것을 확인 할 수 있다.

 

하는김에 Cleanup 전후 변화도 확인 해보자

 

Cleanup 전

ls

결과

result.txt
command_log.csv

 

Cleanup 수행

rm result.txt
rm command_log.csv

 

Cleanup 후

ls

 

파일이 삭제 된것을 볼 수 있다.

 

 

이번 실습을 통해서 단순하고 짧은 Linux 명령어들도 실제 공격자의 정보 수집 과정에서 중요한 역할을 하는 점을 확인 해보았다.

또한 공격자는 정보를 수집하면서 동시에 시스템 내부에서 파일 접근 기록, bash history 등 다양한 흔적을 남기게 된다는 점도 확인 할 수 있었다.
